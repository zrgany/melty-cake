# Melty Cake — المنصة التجارية

منصة طلبات إلكترونية كاملة لـ Melty Cake: واجهة عملاء (عربي RTL، موبايل أولاً) + لوحة تحكم أدمن حقيقية + قاعدة بيانات + مصادقة + نظام تسعير آمن من الخادم.

**هذا تسليم "المرحلة الأولى"** — الأساس الكامل + دورة الطلب الحقيقية (تصفح → تخصيص → سلة → دفع → طلب آمن → متابعة) ولوحة تحكم شغّالة (تسجيل دخول، منتجات، طلبات، إعدادات). القسم الأخير من هذا الملف يشرح ما تبقّى للمرحلة القادمة بصراحة.

---

## 1. ما الذي تم بناؤه فعلياً

- **قاعدة بيانات حقيقية** (Prisma + SQLite/PostgreSQL) بكل الجداول العشرين المطلوبة.
- **مصادقة منفصلة تماماً**: جدول `AdminUser` مستقل عن `User`، جلسات موقّعة (HMAC) في كوكيز httpOnly، ولا يمكن لأي عميل الوصول لأي صفحة أدمن حتى بكتابة الرابط مباشرة (تحقق حقيقي في كل صفحة وكل API، وليس فقط إخفاء الرابط).
- **نظام تسعير آمن بالكامل من الخادم** (`lib/pricing.ts`): عند إنشاء أي طلب، السعر يُقرأ من قاعدة البيانات مباشرة، لا يُثق بأي رقم قادم من المتصفح — تماماً كما طلبت في البند 34.
- **لقطة سعر لكل طلب** (`OrderItem`): تغيير سعر منتج لاحقاً لا يغيّر الطلبات القديمة.
- **القائمة الكاملة** مزروعة بالأسعار الحقيقية كما أرسلتها بالضبط، دون اختراع أي سعر أو نكهة أو منتج.
- **دفع كضيف (Guest Checkout)**: العميل يطلب بدون تسجيل حساب — مناسب أكثر لسرعة الطلب اليومي، مع رابط متابعة آمن (رمز عشوائي، وليس رقم الطلب فقط، حتى لا يستطيع أحد تصفح طلبات غيره بتغيير رقم في الرابط).
- **لوحة تحكم شغّالة**: منتجات (إضافة/تعديل/صور/خيارات وأسعار)، طلبات (فلاتر + تحديث الحالة)، إعدادات (بيانات التواصل + مناطق التوصيل + كوبونات)، ولوحة رئيسية بإحصائيات حقيقية من قاعدة البيانات.

## 2. ⚠️ ملاحظة مهمة عن هذه البيئة (اقرأها أولاً)

كتبت كل هذا الكود يدوياً في بيئة **بدون اتصال إنترنت**، لذلك لم أستطع تشغيل `npm install` أو تجربة السيرفر فعلياً هنا قبل التسليم. الكود مكتوب بعناية وبأنماط قياسية مجرّبة في Next.js، لكن **الخطوة الأولى الحقيقية عندك هي تشغيله محلياً** والتأكد أنه يعمل، وإخباري بأي خطأ تواجهه لأصلحه فوراً.

---

## 3. التشغيل محلياً

**المتطلبات:** Node.js 18.18 أو أحدث.

```bash
# 1) تثبيت الحزم
npm install

# 2) انسخ متغيرات البيئة
cp .env.example .env
# افتح .env وغيّر SESSION_SECRET إلى قيمة عشوائية طويلة (openssl rand -hex 32)

# 3) أنشئ قاعدة البيانات (SQLite تلقائياً، بدون أي إعداد خارجي)
npm run db:migrate

# 4) ازرع القائمة الأساسية + الإعدادات
npm run db:seed

# 5) شغّل المشروع
npm run dev
```

افتح `http://localhost:3000` — يفترض أن تشاهد الموقع بكامل القائمة.

---

## 4. إنشاء أول حساب أدمن

بعد التثبيت، لا يوجد أي حساب أدمن بعد (لم أضع كلمة مرور داخل الكود كما طلبت). طريقتان:

**الطريقة الأسهل — أمر مباشر:**
```bash
npm run create-admin -- "اسمك" "07xxxxxxxxx" "كلمة-مرور-قوية"
```

**أو تلقائياً وقت الزرع:** ضع القيم التالية في `.env` قبل تشغيل `npm run db:seed`:
```
FIRST_ADMIN_NAME="اسمك"
FIRST_ADMIN_PHONE="07xxxxxxxxx"
FIRST_ADMIN_PASSWORD="كلمة-مرور-قوية"
```

بعدها ادخل من: `http://localhost:3000/admin/login`

## 5. متغيرات البيئة (`.env`)

| المتغير | الوصف |
|---|---|
| `DATABASE_URL` | رابط قاعدة البيانات (SQLite افتراضياً، أو PostgreSQL في الإنتاج) |
| `SESSION_SECRET` | مفتاح توقيع جلسات الدخول — **غيّره قبل النشر الحقيقي** |
| `FIRST_ADMIN_NAME/PHONE/PASSWORD` | لإنشاء أول أدمن تلقائياً عبر seed (اختياري) |

لا يوجد أي مفتاح لخدمة خارجية مدفوعة — لا حاجة لأي حساب خارجي لتشغيل المشروع.

## 6. النشر (Deployment)

المشروع Next.js عادي، ينشر على أي مزوّد يدعم Node.js:

**الخيار الأبسط (سيرفر/VPS واحد):**
```bash
npm run build
npm run db:deploy   # يطبّق الجداول على قاعدة الإنتاج
npm run start        # يشغّل السيرفر على المنفذ 3000 (استخدم pm2 أو systemd لإبقائه يعمل)
```
صور المنتجات تُخزَّن محلياً في `public/uploads/products` — هذا يعمل ممتاز على VPS/Docker العادي.

**لو رغبت بالنشر على Vercel أو أي منصة serverless:**
- SQLite لا يعمل جيداً هناك (نظام الملفات مؤقت) — غيّر `provider` في `prisma/schema.prisma` إلى `"postgresql"` واستخدم قاعدة Postgres مُدارة (مثل Neon أو Supabase أو Railway)، الحساب باسمك أنت بالكامل.
- رفع الصور المحلي لن يعمل على serverless (لا يوجد قرص دائم) — يحتاج حينها التحويل لتخزين متوافق مع S3 (مثل Cloudflare R2)، وهذا موضّح كنقطة توسعة في `app/api/admin/products/[id]/images/route.ts`.

**لا يوجد أي ارتباط بحسابي الشخصي أو أي خدمة لا تملك التحكم بها.** كل شيء — الكود، القاعدة، الصور — ملكك بالكامل.

## 7. عمليات يومية

- **إضافة صورة لمنتج:** لوحة التحكم ← المنتجات ← افتح المنتج ← اسحب/اختر صورة في قسم "الصور" أعلى الصفحة.
- **تعديل سعر:** لوحة التحكم ← المنتجات ← افتح المنتج ← عدّل "السعر الأساسي" أو أسعار الخيارات ← حفظ التعديلات. الطلبات القديمة لا تتأثر أبداً.
- **إدارة الطلبات:** لوحة التحكم ← الطلبات ← افتح الطلب ← غيّر الحالة من القائمة المنسدلة (يُحدَّث فوراً، ويُسجَّل في سجل العمليات).
- **إضافة منطقة توصيل:** لوحة التحكم ← الإعدادات ← "مناطق التوصيل" (**مهم:** بدون منطقة واحدة فعّالة على الأقل، لا يقدر أي عميل يكمّل طلبه — أضف منطقة واحدة على الأقل الآن).
- **إضافة رقم الهاتف/واتساب:** لوحة التحكم ← الإعدادات ← معلومات المشروع.

---

## 8. ⚠️ بنود من القائمة الأصلية لم تُضَف — لتجنّب اختراع أسعار

القائمة التي أرسلتها لم تتضمن أسعاراً للعناصر التالية، فتركتها لك بدل اختراع رقم:
- **البوكسات** (Mini Box / Family Box / Party Box) — لا يوجد سعر أصلاً في القائمة.
- **إضافات البوكسات** (فستق حلبي إضافي، صوص شوكولاتة إضافي، أوريو، لوتس...) — بلا أسعار.
- **أحجام وإضافات "صحن السعادة بالككو"** — أُضيفت كخيارات بدون أثر على السعر مؤقتاً (السعر الأساسي فقط 5,000 د.ع) لعدم توفر أسعار منفصلة لكل حجم.

بمجرد ما ترسللي الأسعار الصحيحة، أضيفها فوراً.

## 9. ما تبقّى للمرحلة القادمة

هذا يعادل مشروعاً كبيراً فعلاً، وبنيت الآن الأساس الكامل + أهم دورة عمل (الطلب من أوله لآخره + إدارة حقيقية). التالي بانتظار طلبك للمتابعة:

- حسابات العملاء الكاملة (تسجيل دخول، الطلبات السابقة، العناوين المحفوظة، المفضلة) — البنية التحتية جاهزة، الواجهة متبقية.
- عرض العروض/البانرات من لوحة التحكم على الصفحة الرئيسية (الجدول جاهز في القاعدة).
- إشعارات داخل الموقع + تجهيز Push Notifications لاحقاً.
- بحث فوري داخل الموقع.
- تفعيل PWA (تثبيت على الشاشة الرئيسية).
- رسوم بيانية أكثر تفصيلاً في التحليلات.
- اختبار شامل (Testing) لكل السيناريوهات بعد ما يشتغل المشروع فعلياً عندك.

قلّي "كمّل" أو حدد أي بند تريد الأولوية له، وأكمل البناء مباشرة.

## 10. سجل تدقيق (تم لاحقاً، بعد التسليم الأول)

راجعت المشروع كاملاً (كل الملفات + هذا الـREADME) ووجدت وأصلحت 4 مشاكل حقيقية:

1. **5 منتجات كانت تعرض "يبدأ من" بسعر أعلى من أرخص خيار فعلي** (مثال: كيك الحليب كان يعرض 8,500 كسعر بداية رغم أن القطعة المفردة 1,500) — صححت `basePrice` في `prisma/seed.ts` لكل من: كيك الحليب، البسبوسة، خلية النحل، أكواب السعادة، الدولمة. هذا لم يؤثر على صحة الفوترة الفعلية (السعر الحقيقي كان دائماً يُحسب صح من مجموعة الخيارات)، لكنه كان يعرض رقماً مضللاً للعميل قبل الدخول للمنتج.
2. `tailwind.config.ts` كان ناقصاً مجلد `lib/` من قائمة الملفات الممسوحة — لا يوجد أثر ظاهر حالياً لكنه ثغرة إعداد حقيقية. تم إصلاحها.
3. أضفت إعداد `prisma.seed` المعياري في `package.json` حتى تعمل أوامر Prisma الرسمية (`prisma db seed`, `prisma migrate reset`) وليس فقط أمري المخصص.
4. أضفت `eslint` + `eslint-config-next` + `.eslintrc.json` لأن `npm run lint` ما كان ليعمل بدونها.

**تم التحقق يدوياً وبرمجياً (سكربتات فحص كتبتها لهذا الغرض) من:** كل الـimports الداخلية (120) تطابق تصديرها الفعلي، كل نداءات fetch (14) تطابق API routes الحقيقية والـmethod الصحيح، كل استخدامات Prisma تطابق أسماء الجداول والحقول في الـschema، تطابق checkoutSchema مع البيانات الفعلية المُرسلة من نموذج الدفع حرفياً، فصل الكوكيز بين العميل والأدمن، وجود تحقق مصادقة مستقل في كل API route أدمن (وليس فقط الاعتماد على middleware).

**لم أستطع تشغيل `npm install` / `next build` / `next lint` فعلياً** — هذه البيئة بدون اتصال إنترنت (تأكدت من ذلك بمحاولتين). هذه هي الخطوة الحرجة التالية وتحتاج تُنفَّذ عندك.
